# Ketchup

向用户汇报自其在 `/ketchup` 之前最后一条消息以来本次会话发生了什么，并帮助用户理解每项变化，而不只是进展到哪。然后把每一件在等用户拍板的事列出来，让用户仅凭你的回复就能拍板。通知和子代理结果不算用户的消息。假定用户记得自己最后一条消息，之后一概不记得。

用 [`/bro`](../bro/SKILL.md) 的语气，不做它的任务：平实的话、短句、没有行话，像一个人向另一个人同步近况。说对用户而言什么变了，而不是你怎么做的。说「the tests pass」，不说「CI is green」。除非用户行动需要，否则省略哈希、文件路径、命令、构建号和测试数。每个 PR、分支或代理用用户认得的名字称呼，不要用你发明的标签。如果一个事实需要上下文才有意义，要么给上下文，要么别提。

## 收集发生了什么

本轮保持只读。只用已有的东西做图形：不改代码、不启动应用或任务、不发任何东西。收集你自己自那条消息以来的工作、子代理的报告，以及本会话中其他任何人的消息。核对每个本会话触及的 PR、CI 运行或代理的当前状态。把你将展示的每个数字对照其来源事实核实，纠正了就说一声。

行动项是只有用户能做的决定或步骤，比如产品选择、批准、不可逆操作，或你缺少的权限。包括所有仍在等用户的，哪怕是在其最后一条消息之前提出的。你自己还能做的工作不是行动项。绝不为了填满回复编造一个决定。用户没有要求、工作也不需要的步骤不是行动项，除非它不可逆且在等用户：那样给它一行、不加图形。

一个决定可以覆盖多项，比如一组等待合并的每个 PR。对每一项，收集它的链接、它给用户改变什么、你的推荐背后的证据、它的风险，以及你的推荐。决定需要而你不掌握的事实写「unknown」。没有的链接不要放。

## 写回复

字数花在决定上，不花在故事上。发生了什么保持在 100 词以内，图片不计；更少发生就更短。省掉对用户没有任何改变的工作。每项约 30 词。回复随项目数增长：两项时全篇远低于 150 词（图片不计），三十项时则远超。绝不为控制字数砍项或缩项：不用计数代替清单，不用链接代替一项。链接可以加深，但回复本身必须足以拍板。

开篇一句短话点明什么在等用户，或者说没有。细节在行动项里。如果什么都没发生、也没在等用户，就说一声然后停。

然后展示发生了什么，图在前。先内嵌工作产出的截图和视频，再放任何解释变化的图示。然后对用户要求的每一件事各一条短 bullet 总结：结果如何，以及它完成了、还在跑、失败了还是没检查。每行写成你口头会说的方式：「Search was slow from a missing index」，不是「Search review: done」或「Slow search: missing index」。途中发现并修复的 bug要点名。每行单独读也必须成立。绝不把仍在等用户的标成完成，行动项里说过的内容不要重复。总结之下，至多三行短话，写改变用户认知或待办的内容。再用一行点出你自己还能做的剩余工作。

然后列行动项。问出用户拥有的那个决定，比如合并、批准或选择，并给出你的推荐。你会先做的步骤放进推荐里。必须先行的事项、以及不可撤回的事项，也放进推荐。给出决定所涉每个 PR、issue 或代理的编号或链接，在选项之间的决定里同样如此。

让形状贴合决定。关于一项的决定是一条 bullet：决定本身、你的推荐、它给用户改变什么、推荐背后的证据，以及它的风险，项目名只出现一次。多项共用一个决定时，决定和推荐写一次，再给每项自己的 bullet，风险最高的在前：它的链接和名字、它给用户改变什么、推荐背后的证据，以及它的风险。只在某项的推荐与整体决定不同时才单独点名它的推荐。每项的风险都要给，哪怕很低，比如「Low risk: only the colors change.」等待的代价只有在超出单纯延迟时才说，比如有截止日期或会丢数据。

对于在选项之间的决定，给出工作权衡过的每个选项：各自给用户带来什么、代价是什么，以及现状（如有）。这些代价就是这个决定的风险，所以不再单加风险行。当上面的截图已展示各选项时，在每个截图下方写该选项的收益和代价。

## 图形

图形是一张图：截图、视频、Mermaid 图示、从数据渲染的图表，或生成的图片。Markdown 表格不是图形，哪怕带前后对比列。

当某样东西作为图比作为句子更容易理解时，画它：设计或系统如何工作、一个 PR 栈或依赖链及每个 PR 的状态、一次修复的前后对比，或并排的选项。绝不画状态清单、行动项清单，或没有任何连线相连的方框。绝不把同一个事实说两遍，无论在文字里还是跨图形。

每张图形保持一眼能读懂的尺寸：至多六个方框，每框至多八个词。标签写成人们会说的平实词语，不要「Tests: pass」这样的标签。需要一句话才能成立的事实属于正文，或者哪里都不属于。

当变化可见时内嵌截图和视频，而不是只给链接。如果某个可见变化没有截图，在它的总结行标注「No screenshot yet」，并在那里说明屏幕上变了什么。图形和图表从你掌握的事实画：连接关系用 Mermaid 图示，数字用从数据渲染的图表。绝不编造数字，绝不画或生成一张你没有截取过的屏幕。只链接真实存在的产物。
