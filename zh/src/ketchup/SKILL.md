# Ketchup

帮用户补上自 `/ketchup` 之前他写的最后一条消息以来这次聊天里发生的变化，而且不只是汇报进度，要让他理解每处变化。然后把每一项等他拍板的决定列出来，让他只凭你的回复就能拍板。通知和子代理的结果不算他的消息。默认用户只记得自己的最后一条消息，之后的事一概不记得。

语气用 [`/bro`](../bro/SKILL.md) 的腔调，但不是它的任务：大白话、短句子、不用术语，像一个人向另一个人补课。说对用户而言变了什么，而不是你怎么做到的。说「测试通过了」，不说「CI 绿了」。除非用户行动时真的需要，否则不要出现哈希、文件路径、命令、构建号和测试数量。每个 PR、分支或 agent 都用用户熟悉的名字称呼，不用你自己发明的代号。一个事实需要上下文才能理解，要么给出上下文，要么干脆不讲。

## 收集变化

这一轮保持只读。配图只用已有的东西：不改代码，不启动应用或任务，不发任何消息。收集你自那条消息以来的全部工作、子代理的报告，以及这次聊天里其他人的消息。逐一核对这条聊天碰过的每个 PR、CI 运行或 agent 的当前状态。你要展示的每个数字都和它来源的事实核对，改过哪处就说明哪处。

行动项是只有用户能做的决定或步骤，比如产品取舍、审批、不可逆的操作，或你没有权限做的事。所有仍在等用户的都要列进去，哪怕是早于他最后一条消息提出的。你自己还能接着做的活不算行动项。绝不为了凑回复编造决定。用户没要求、工作也不需要的步骤不算行动项——除非它不可逆且在等用户：那种只给一行字，不配图。

一个决定可以覆盖多项，比如同一批等待合并的每个 PR。每项都收集：它的链接、它给用户改变了什么、你给出建议的依据、它的风险，以及你的建议。决定需要而你不知道的事实写「未知」。没有的链接不要硬给。

## 写回复

字数花在决定上，别花在故事上。发生的事控制在 100 词以内（配图不算），事情少就更短。对用户没有任何影响的工作略去。每项约 30 词。回复随事项数量增长：两项总共要明显低于 150 词（配图不算），三十项则要长得多。绝不为了控制字数砍掉或压缩事项：不能用一个数字代替清单，也不能用一条链接代替一项。链接可以增加深度，但只凭回复本身必须足以做决定。

开头一句短话，点明有什么在等用户，或者说没有。细节放在行动项里。如果什么都没发生、也没有事等用户，说一句就停。

然后展示发生的事，图先上。先内嵌工作产出的截图和视频，再放解释变化的图示。然后对用户要求的每件事用一条简短要点收尾：结果如何——完成了、还在跑、失败了，还是没检查。每行都按你口头会说的写法：「搜索之前很慢，缺了一个索引」，而不是「搜索评审：完成」或「慢搜索：缺索引」。过程中发现并修掉的 bug 也要点出。每行单独读出来都必须成立。还在等用户的事绝不能写成已完成；行动项里已经讲过的不重复。摘要下面再给至多三行简短的话，只放会改变用户认知或行动的内容。最后用一行说明还有哪些你自己能接着做的活。

然后列行动项。把用户拥有的决定直接问出来，比如合并、批准、选择，并给出你的建议。你会先做的步骤写进建议里；必须先发生的事、以及不可逆的事也一样。每个决定涉及的 PR、issue 或 agent 给出编号或链接，即便决定本身是在几个选项之间做选择也照给。

格式跟着决定走。关于单项的决定就是一条要点：决定、你的建议、它给用户改变了什么、依据、风险，事项名只出现一次。多项共享一个决定时，决定和建议只写一次，然后每项一条要点，风险最大的排前面：链接和名字、它给用户改变了什么、依据、风险。某项的建议和总体决定不同时才单独标注。每项的风险都给，哪怕很低，比如「低风险：只改了配色」。等待的代价只有在不止是拖延时才说，比如有截止日期或会丢数据。

如果决定是在几个选项之间选择，把工作权衡过的每个选项都列出：各能得到什么、付出什么，有现状就写现状。这些代价就是这个决定的风险，不用再单列风险行。如果上面的截图已经展示了各选项，就把每个选项的得失写在它的截图下面。

## 配图

配图是图画：截图、视频、Mermaid 图示、用数据渲染的图表，或生成的图片。Markdown 表格不是配图，哪怕有前后对比的列。

某件事画出来比写句子更容易懂时就画：一个设计或系统怎么运转、一个 PR 栈或依赖链及每个 PR 的状态、一次修复的前后对比，或几个选项的并排比较。绝不画状态清单、行动项列表，或毫无关联的一堆框。一个事实无论在文字里还是跨配图，都不要讲第二遍。

每张配图保持一眼能读懂的大小：最多六个框，每个框最多八个词。标签用人会说的大白话写，不要用「Tests: pass」这种标签。需要一句话才能讲清的事实放进正文，要么就不讲。

变化肉眼可见时，截图和视频要内嵌，不要只给链接。某处可见变化没有截图，就在摘要行标注「暂无截图」，并在那里讲清屏幕上变了什么。图示和图表只画你掌握的事实：连接关系用 Mermaid 图示，数字用数据渲染的图表。绝不编造数字，绝不画或生成你没有截取过的屏幕。链接只给真实存在的产物。
