# Figure it out

任务不匹配任何 playbook（流程清单）时，就设计一个。写任何代码之前，交付物是工作流本身：一个阶段序列，把严格性按任务缩放，运行科学方法，并留下人离开后可以审计的决策轨迹。

## 开始

开一个 todolist，第一项是读 **poteto-mode** 技能的 Principles 一节。然后把下面的阶段加为 todo。

## 阶段 A：Frame

先落地，再承诺。在能陈述以下内容之前不开跑：

- 以可证伪谓词表述的完成定义（**prove-it-works** 原则技能）。
- 量化的范围：粗略单位和工作量，加上 grounding 浮现出的阻塞项。
- 严格性等级，宁高勿低。单向门和高 blast radius 多给。可逆的低风险步骤少给。严格性是门和工件，不是「再努力一点」。

承诺长跑之前，先呈现框架和取舍。可逆的工作继续推进（**never-block-on-the-human** 原则技能），但一次多小时的长跑值得一个检查点。

## 阶段 B：设计工作流

分解为原子的、可独立落地的单元。按最危险的未知优先排序。脚手架和验证先于功能（**foundational-thinking** 原则技能）。

- 在工作开始前搭好验证宿主（harness），基线取自改动前状态，这样检查读作「旧值 vs 新值」。
- 对单向门式的设计决策，跑 **architect** 技能（它内部跑 **arena**）。形状已经具体化的机械工作跳过它。对已定设计再跑一次 arena 是过度工程（**laziness-protocol** 原则技能）。
- 决定什么扇出。只在接缝处并行，并给每个 worker 自己的工作树或分支（**separate-before-serializing-shared-state** 原则技能）。不要过度扇出。按 **poteto-mode** 技能的 Subagents 一节，为每项工作选子代理推理强度。
- 把设计好的阶段清单写下来。人审查的就是那份清单。

然后执行设计。把它的步骤作为具体条目加进 todolist，插在 Phase C 和 Phase D 条目之间。每一步都在 Phase C 的循环纪律下运行，并把 Phase D 的日志穿插其中，每落地一步记一行，而不是把整条轨迹留到最后。

## 阶段 C：跑循环

每个单元是一次实验。陈述假设，做最小的改动，在真实工件上对照谓词测量，有进展就保留，没有就回滚。应用 **sequence-verifiable-units** 原则技能，在开始下一个单元前验证当前单元，而不是把检查攒到最后一批做。

- 通过检查工件来验证，绝不信自我报告。当某样东西太容易通过时，先怀疑观察方法，再怀疑系统。
- 委派的工作配一个裁判。如果 worker 骗过了门，重置并加固契约。如果门本身错了，在独立的改动里修门，而不是绕过它。
- 结论是 VERIFIED、NOT VERIFIED 或 INCONCLUSIVE。Inconclusive 不是 pass。不隐藏负面结果。

## 阶段 D：保留审计轨迹

通过 **show-me-your-work** 技能记录这次运行。figure-it-out 的工作通常足够重要，值得把轨迹提交，让审查者能在 PR 里读到。轨迹加 diff，才让人能回来看并信任这份工作。

## 阶段 E：验证并交回

在真实产品上对照 Phase A 的谓词检查整体，而不只是宿主（harness）。把反复出现的纠正编码成一道门、一条 lint 规则、一个检查或一个脚本（**encode-lessons-in-structure** 原则技能）。

**回复：** 你设计的 playbook（流程清单）、严格性等级及理由、决策轨迹路径、对照谓词验证了什么、还有什么 open。
