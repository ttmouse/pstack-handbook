# Fix Root Causes

调试时，修故障本身，而不是它浮现的地方。症状是错误状态变得可见的位置。根因是系统第一次做了不该做的事、或没能处理一个该处理的状态的位置。

**为什么：** 治症状会把证据藏起来，让故障自由地换地方浮现。每治一次症状，系统就更难推理一分，因为代码里从此带着一个没人点名的 bug 的 workaround。

**模式：**
- 先复现。
- 每一步都问「为什么」，直到答案是代码里的一个错误决策，而不是更早决策的后果。
- 卡住就加观测。读真实的错误和真实的状态。不要猜。
- 问触发症状的那个状态是不是合法状态。如果系统允许处于该状态，那在那里出错的代码就是根因，在那里处理这个状态就是修复。如果这个状态根本不该存在，在出错处加检查就是把 bug 藏起来。去找产生这个状态的东西。守卫、重试、吞掉的错误、钳位值、被丢弃的状态，都是藏 bug 的常见方式。
- 当某件事只在重启之后才失败，先怀疑持久化状态：配置文件、缓存、锁文件、序列化的状态。
- 检查模式，而不只检查这一例。找到每一处同样的故障，全部修掉。
- 如果一个 workaround 需要一段长注释来自圆其说，错的是代码。修代码，不是修注释。
- 如果那个决定性事实是深挖才找到的，提出一个便宜、常开的信号，让它第一眼就能看出来。
