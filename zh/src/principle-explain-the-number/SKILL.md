# Explain the Number

- **在跑之前先写下决策。** 说出哪个结果会改变决策，以及噪声底线。当运行间波动大于效应时停止。
- **问「为什么不是翻倍？」** 说出限制结果的资源或代码路径，比如一个核心、一把锁、磁盘、网络，或压测工具本身。从 profile 或运行期间采集的系统计数器里拿到它，然后映射回源码。读代码得出的猜测不是限制因素。如果你说不出为什么这个数字没有好上两倍，你就不知道自己测的是什么。
- **列出这个数字还可能在测量什么，并用证据逐个排除。** 常见嫌疑是：错误、被跳过或被缓存的工作、从未运行到的代码、未调优的一方（有一边留在默认设置）、噪声，以及端到端小到无关紧要的一个环节。
- **把证据和数字放在一起。** 把运行次数、波动幅度和限制因素写进笔记或一个链接的产物里。

对性能数字，用 [benchmark-checklist](../benchmark-checklist/SKILL.md) 技能跑完整流程。对评测结果，对每次试验问同样的问题：每次运行都完成了任务吗，差距在多次试验和多个模型上都成立吗，这个场景重要吗。

在这些情况下你就是跳过了这一步：运行开始时没有写下会改变决策的结果；数字背后的证据没有运行次数、没有波动幅度、没有指名的限制因素；或者省下的时间比被改动环节原本耗时还多。

本原则不同于 [Prove It Works](../principle-prove-it-works/SKILL.md)，后者检查一个输出是不是真的。
