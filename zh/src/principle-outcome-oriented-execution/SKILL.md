# Outcome-Oriented Execution

以预期的、可验证的终态为优化目标，而不是维持平滑的中间状态。

**为什么：** 让每个中间步骤都完全稳定，往往会造出变成长期债务的临时兼容代码。收敛到目标架构，在明确的验证边界上证明正确性。

**核心规则：**
- 终态完整性优先于过渡期稳定性
- 当破坏是有计划的、有范围的、可逆的，中间阶段的破坏可以接受

**护栏：**
- 只用于有明确阶段边界的有计划重写和迁移
- 宣布哪些地方允许临时破坏
- 迁移期间在正在改动的区域保留高信号的检查
- 计划完成时要求完整的静态和运行时验证
