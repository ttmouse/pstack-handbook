# Outcome-Oriented Execution

优化目标是那个可验证的最终状态，而不是维持平滑的中间状态。

**为什么：** 让每个中间步骤都完全稳定，往往会产生临时兼容代码，最后变成长期债务。要向目标架构收敛，在明确的验证边界上证明正确性。

**核心规则：**
- 终态完整性优先于过渡期稳定性
- 中间态出问题是可以接受的，前提是它经过计划、范围可控、且可回退

**护栏：**
- 只用于有明确阶段边界的计划性重写和迁移
- 明确声明哪些地方允许临时出问题
- 迁移期间，对正在改动的区域保留高信号的检查
- 计划完成时，要求通过完整的静态与运行时验证
