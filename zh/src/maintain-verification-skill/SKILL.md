# 维护一个验证技能

在 Codex 上，先读[平台映射](../poteto-mode/references/codex-tools.md)（包括其中的逐技能说明），再执行本技能。

在 GitHub Copilot 上，先读[平台映射](../poteto-mode/references/copilot-tools.md)（包括其中的逐技能说明），再执行本技能。

在 Muse 上，先读[平台映射](../poteto-mode/references/muse-tools.md)（包括其中的逐技能说明），再执行本技能。

在 Antigravity 上，先读[平台映射](../poteto-mode/references/agy-tools.md)（包括其中的逐技能说明），再执行本技能。

应用一变，功能地图就开始腐烂。本技能是 `/create-verification-skill` 生成的技能（或任何带功能地图的项目本地验证技能）的保养闭环。严谨的单位是功能，不是每句话：每个功能文件都要有源码覆盖和活体使用，而不是把每一条 bullet 都做成终态。

## 结果

三选一，并说出来是哪个：

- **clean** —— 每个功能都拿到了源码和活体覆盖；没有值得发布的东西。不开分支，不开 PR。
- **changed** —— 一个 PR 发布已证明的文档、宿主或地图修正。
- **blocked** —— 覆盖无法完成，或一个已证明的修正无法安全发布。精确说出是什么挡住了它。

## 编辑范围

只编辑验证技能自己的目录（它的 SKILL.md、features/、以及它拥有的宿主脚本）。运行期间绝不编辑产品代码：地图描述的某个行为应用已经不再有，要么是文档漂移（修地图），要么是产品回归（报告它，不要在文档里糊过去）。

## 巡检

0. **定位目标。** 找到要维护的验证技能：正文带 launch/drive 小节和功能地图的项目本地技能（`.claude/skills/verify/`，或旧生成器的 `.claude/skills/verify-*/`）。多个候选 → 问是哪个；一个没有 → 停下来指向 `/create-verification-skill`，不要凭空发明目标。

1. **索引卫生。** 读功能地图 README，glob 它的同级文件。修缺失、多余、重复、死链条目。轻量；不生成清单。

2. **源码波次。** 每个功能文件一个只读子代理，并发启动。每个从源码解释「这个用户可见功能是怎么工作的？」，带引用标记疑似文档漂移，并返回一个简明的活体验证配方。子代理绝不驱动应用，绝不编辑文件。返回形状：功能摘要 / 源码入口 / 疑似漂移或无 / 一个配方。

3. **对账。** 每个功能文件都有一个返回的摘要。把重叠的配方合并成尽量少的应用状态。抽查有引用的漂移；干净的主张不要重新证明。扫一遍最近的变动，找地图上缺失的用户可见表面——判定缺失前要求一个具体的源码路径。

4. **活体巡检。** 即使源码看起来干净也必须做。协调者拥有所有驱动；遵循验证技能自己的 launch 模型——服务器和 UI 用一个长活实例串行驱动，短命 CLI 每次驱动用一个全新隔离会话（技能的 Launch 小节说了算，不是本技能）。每个功能至少使用一次，并在整个巡检中守住三条不变量，无论怎么失败：(1) 自实例上次做出意外之事以来没做过健康检查的实例绝不驱动——首次驱动前 doctor，会话是单位时每个新会话 doctor，任何一次驱动失败后再 doctor，doctor 看不见失败（健康进程上 UI 卡死）时，重置到已知状态或重新启动，不要抱着侥幸；(2) 已采集的证据要在每次清理后存活，在指定位置核实，不是假设；(3) 驱动启动的任何东西都不得活得比这次驱动的作用久——失败迭代的残留无论会话卡死、退出还是共享都要清理（对共享实例，清理残留，不是实例）。技能漂移导致的 doctor 失败就是漂移：在编辑范围内修掉它并重试一次——重启这个修复所失效的东西，仅此而已——之后才能把巡检标为 `blocked`。到不了的功能只有拿到具体前置条件（鉴权、授权、OS、外部状态）和尝试过的路径才算 `verified-unreachable`；地图漏写了那个前置条件，就是漂移。triage 得出的任何宿主修复，发布前都要重新活体驱动一遍。最终 teardown 在本次运行最后一次驱动之后——包括那些重新证明——所以没有任何东西活得比这次运行久（证据留下，按技能）。

5. **Triage（分诊）。** 用户视角描述错误或缺失 → 文档漂移，修。行为正常但宿主演不了 → 宿主缺口，修；宿主修复遵循与生成相同的 helpers 规则（脚本可执行、调用方式写在技能正文）。应用行为真的坏了 → 产品缺口；给用户记下来，不进这个 PR。

6. **发布或停止。** changed：一个已证明修正的 PR，先重读每个改过的文件。clean 或 blocked：不开 PR，诚实报告结果和覆盖。

把简明的运行笔记（覆盖的功能、到不了的前置条件、确认的漂移、结果）放在临时位置；不提交它们。
