# Sequence work into verifiable units

把工作排成一串小单元，每个单元都以一个你能检查的状态收尾，当前单元没变绿就不前进。

**为什么：** 在引发它的那个单元就被抓住的破坏，定位起来很便宜。在一批之后才被抓住的破坏已经被埋起来了，而你已经在一个坏掉的基础之上继续建造了。把这些单元按顺序排成审查者可以重放的交付，就把「信我」变成了「看它先红后绿」。

**执行。** 在扫荡、迁移或任何一批相似编辑里，验证每一个改动之后再开始下一个。每个单元都是一个前后括号：已知良好的状态、一个改动、跑检查、再前进。先 rebase 到干净的 trunk 上，让每次检查都对着真实的基线。当杠杆（lever）替你做编辑时，逐单元检查几乎免费。也照样跑。

**交付。** 按能证明工作的顺序堆叠提交和 PR。标准形状是：先放失败的测试，再在上面放修复。其他的故事顺序也是一种先减法后重塑、先采基线后施处理、先脚手架后功能。每个提交自己就能落地，整个序列读起来是一段论证。

这是 **prove-it-works** 原则技能的排序配套——后者保证每次检查是真的，**build-the-lever** 原则技能保证逐单元检查便宜。
