### Eval

**实验设计归你。计划、盲测、运行、综合。**

**盲测红线：**

- 候选者能看到的任何目录、文件、提示词里，不得出现 eval、test、judge、experiment、rubric、score、compare、benchmark、candidate、arena 这些词。
- 候选提示词要像一个自然的用户请求。说目标，不说元层面。
- 不给引出思维链的提示。不要让候选者列举它用了哪些 skill、原则、文件。可以一般性地要设计说明，然后从代码形态判定是否跟了流程，而不是听它自述。
- 目录和 slug 命名要消毒。用用户真的可能取的项目风格名字。
- 不要告诉候选者还有其他候选者。
- 裁判可以知道自己在当裁判，但它看到的输出只能带消毒后的标签，绝不能带模型名。
- 对比两个变体：一个裁判、一轮、同一把尺子给两套输出打分，且不知道每套输出来自谁。

**步骤：**

1. **定框。** 说明被测的是哪个变体、什么行为算成功。只为裁判写评分规则（3–6 条具体标准）。对候选者保密。
2. **搭建消毒后的环境。** 每个候选者一个工作目录，装好对应变体。把一个自然任务会有的上下文都种进去：项目骨架、候选者自然会读的 skill。
3. **写一条自然提示词。** 用户会敲的那句话。不泄漏任何被测量的东西。
4. **并行起 N 个候选者**，用不同模型，按 **arena** 技能的 Phase B。各自在消毒后的目录里工作。给每个候选者同样的提示词。按 poteto-mode 的 Subagents 一节为每个子代理选合适的推理档位。只做分发、轮询、打包结果的代理，用 `swarm workers` 模型、medium 档。
5. **起一个盲裁判**，用不同模型家族，按 **arena** 技能的 Phase C。裁判看到的输出只带消毒后的标签和评分规则，绝无模型名。
6. **从 transcript 而非自述验证流程。** 读每个候选者在 Claude Code 每项目 transcript 目录下的本地 transcript：`${CLAUDE_CONFIG_DIR:-$HOME/.claude}/projects/<encoded-cwd>/`，`node <plugin>/skills/reflect/scripts/claude-project-dir.mjs` 会打印这个路径。不要跨 `${CLAUDE_CONFIG_DIR:-$HOME/.claude}/projects/` 做 glob——那会越过工作区边界，读到无关项目的私人聊天。看每个候选者实际打开了哪些文件。流程遵循度按它真读过的文件加代码形态评分，绝不信它自己的声明。
7. **自己从头到尾读每个候选者的输出。** 和裁判的裁决对照。分歧意味着某个模型有偏，或评分规则有歧义。综合结论。

**汇报：** 被测变体、评分规则、每个候选者的笔记、裁判裁决、你的综合判断、以及是否晋级该变体的建议。
