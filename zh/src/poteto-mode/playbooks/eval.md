### Eval

**你拥有实验设计。计划、盲测、运行、综合。**

**盲测的非协商项：**

- 候选者可见的任何目录、文件或提示词里，不出现 eval、test、judge、experiment、rubric、score、compare、benchmark、candidate、arena 这些词中的任何一个。
- 候选者的提示词看起来像一个自然的用户请求。陈述目标，不谈元层面。
- 不给引出思维链的提示。不要让候选者列出它用了哪些 skill、原则或文件。泛泛地要设计笔记，从代码形状而非自述来评定思维链遵循度。
- 目录和 slug 名做净化处理。用用户真的可能起的项目形名字。
- 不告诉候选者其他候选者的存在。
- 评委可以知道自己在评审，但它看到的输出只带净化后的标签，绝不带模型名。
- 对比两个变体时：一个评委在单一尺度上、单次 pass 里给两组打分，且不知道每组来自哪里。

**步骤：**

1. **框定。** 说明被测的是什么变体、什么行为算成功。只为评委写评分标准（3-6 条具体判据）。对候选者保密。
2. **搭建净化过的环境。** 每个候选者一个工作目录，变体就位。布置任何自然任务会有的上下文：一个项目骨架、候选者自然会读的 skill。
3. **撰写一个自然的提示词。** 用户会敲的那句话。不泄露任何被测量的东西。
4. **派生 N 个并行候选者**，按 **arena** skill 的 Phase B 用不同模型。每个都在自己的净化目录里工作。给每个相同的提示词。按 Subagents 一节为每个子代理挑选与任务匹配的推理档位。
5. **派生一个盲测评委**，按 **arena** skill 的 Phase C 用不同模型家族。评委看到的输出只带净化标签和评分标准，绝无模型名。
6. **从转录而非自述验证思维链。** 在 Claude Code 的 per-project transcripts 目录 `${CLAUDE_CONFIG_DIR:-$HOME/.claude}/projects/<encoded-cwd>/` 下读每个候选者的本地转录，`node <plugin>/skills/reflect/scripts/claude-project-dir.mjs` 会打印这个路径。不要在 `${CLAUDE_CONFIG_DIR:-$HOME/.claude}/projects/` 上做 glob。那会越过工作区边界、读到无关项目的私人聊天。看每个候选者实际打开了哪些文件。从它真正读过的文件加上代码的形状来评定思维链遵循度，绝不信候选者自己的主张。
7. **亲自通读每一个候选者的输出**，从头到尾。与评委的裁决对照。分歧意味着某个模型有偏差或评分标准有歧义。综合结论。

**回复：** 被测变体、评分标准、每个候选者的笔记、评委裁决、你的综合结论，以及是否晋升该变体的建议。
