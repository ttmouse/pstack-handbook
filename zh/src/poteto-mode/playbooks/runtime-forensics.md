### 运行时取证

**你拥有的是诊断。对活着的进程做插桩，不要从源码空想。** 交付物是一份带引用的诊断，不是修复。

1. 通过 driver 技能在匹配的面上捕获活着的信号：进程打转用 CPU profile，内存泄漏用堆快照，视觉毛刺用 CDP trace。要真实产物，不要猜测。
2. 把产物还原成铁证：热路径上的那个函数、从泄漏对象到 GC root 的保留链、没有输入却还在触发的那个循环。在子代理里解析大产物（**guard-the-context-window** 原则技能），把还原出的发现在主线程保留。按 Subagents 一节，为这份工作选子代理的推理等级。
3. 先证明机制再相信它。通过 CDP eval 向运行中的进程注入插桩，或不打热重载直接热改活代码，便宜地确认假设。
4. 把发现映射回源码：文件、符号、分配或调度的那一行。
5. 吞吐量检查点保持一行：`throughput checkpoint: n/a, read-only forensics`。

**汇报：** 捕获的信号、还原出的发现、你如何证明机制、源码位置、产物路径。除非被要求，不做修复。原因已知后交回 Bug fix 或 Perf。
