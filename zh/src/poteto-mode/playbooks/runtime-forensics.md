### Runtime forensics

**诊断归你。给活进程插桩，不要对着源码空想。** 交付物是一份带引用的诊断，不是修复。

1. 通过 driver skill 在匹配的界面上抓活信号：CPU 打满的进程用 CPU profile，内存泄漏用堆快照，视觉毛刺用 CDP trace。要真实产物，不要猜测。
2. 把产物还原成冒烟的那一发：热路径上的那个函数、从泄漏对象到 GC root 的引用链、无输入却在空转的那个循环。大型产物的解析放到子代理里（**guard-the-context-window** 原则技能），还原后的发现留在主线程。按 poteto-mode 的 Subagents 一节为每个子代理选合适的推理档位。
3. 先证明机制再相信它。通过 CDP eval 给运行中的进程注入插桩，或热修活代码而不重载，把假设便宜地确认掉。
4. 把发现映射回源码：文件、符号、分配或调度的那一行。
5. 吞吐检查点保持一行：`throughput checkpoint: n/a, read-only forensics`。

**汇报：** 抓到的信号、还原后的发现、怎么证明的机制、源码位置、产物路径。没被要求就不修。原因明确后交回给 Bug fix 或 Perf。
