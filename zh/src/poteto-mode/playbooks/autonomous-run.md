### Autonomous run（自主运行）

**你拥有退出条件。定义完成，然后一路推进到位，中途不停。**

1. 在第一轮迭代之前，把退出条件表述为一个可检查的谓词（测试全绿、repro 修复、全部 N 个 PR 合并、像素 diff 为零）。
2. 用 Claude Code 的 `loop` skill（内置 skill，不是 pstack skill）挑选唤醒机制。有一个要观察的事件（CI、一次合并、一个 ref 前进）就配一个 watcher 子代理，事件发生时唤醒你，并以长时间的定时心跳作为兜底。没有事件就用固定间隔的心跳，间隔按结果值得重新检查的时点来定。按 Subagents 一节为每个子代理挑选与任务匹配的推理档位。
3. 每轮迭代只做证据能支撑的最小改动，对照谓词验证它，有进展就提交，没帮助的改动就丢弃。"可能有帮助"的双保险会被回滚，不会留着搭车。
   通过 **sequence-verifiable-units** 原则 skill 排布工作，逐个单元先验证再做下一个，而不是把检查攒到最后一起做。
4. 运行中途发现的、支持目标的问题归你管。坏掉的 skill、相关 bug、不稳定的 verifier、review 噪音、工具故障、被遗弃的后续事项、可修复的漂移——都通过 poteto-mode 自己处理。把带外修复放进单独的 PR。不要把可逆的工作留给人，也不要用 `AskUserQuestion`。只上报不可逆操作、任何实验都定不下来的真正的产品或偏好抉择、或真正的死胡同。让谓词保持为主动力，每次顺手修复之后回到谓词上。
5. 每轮迭代都通过 **show-me-your-work** skill 做检查点：一行记录改了什么、谓词有没有前移。
6. 谓词满足时停止。平台期不是停止，继续推进并换一个打法去突破。真正的死胡同要上报而不是空转，绝不放宽谓词来宣布胜利。

**回复：** 退出条件、跑了几轮迭代、哪些落地了、哪些被丢弃了、谓词的最终状态。
