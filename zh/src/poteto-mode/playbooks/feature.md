### Feature

**设计归你。计划、评审、验证。** 实现委托出去。主导权留在你手里。

1. 追溯受影响的子系统。
2. 用 `architect` 定形态。
3. 把吞吐检查点写成四个 todo 项。某个维度真的不适用（单文件、无扇出）时保留该项并写 `n/a: <原因>`，不能删掉：
   - **前置阻塞步骤。** 扇出之前要过的闸门。
   - **独立工作流。** 不相交的文件、服务、层可以并行。有共享写入就必须串行。
   - **共享可变状态。** 默认拆分目标（**separate-before-serializing-shared-state** 原则技能）。只有真正的不变量才串行。
   - **最小安全分解。** 如果一个 worker 最优，说明为什么。
4. 把写代码委托给子代理，使用你配置的 feature 模型（默认见 poteto-mode 的 Models 一节），并给一个具体范围（文件路径、具名的数据形态及其组织结构——按 **principle-model-the-domain**：散落布尔量上建状态机、分支上表格/注册表、重复形态假设上类型化模型——这些要在委托写逻辑之前定好；以及成功判据）。按 poteto-mode 的 Subagents 一节为每个子代理选合适的推理档位。当实现存在多种合理形态（错误处理、抽象层、测试结构）时，改用 **arena** 技能委托，让 runners 呈现备选方案、由 cross-judge 守住选型。强制要求：不允许「有理由就跳过」的逃生口，Laziness Protocol 也不能覆盖它（这里赚的是评审分离，不是省行数）。不允许起子代理时，由子代理自己直接持有 diff 并保持同样的评审分离，也算满足。不接受「待命中」等嵌套代理的回复。**每个写文件的委托都给它自己的工作树**（用 `isolation: "worktree"` 启动，或给它一个独占分支），且不要在委托仍持有的工作树里写文件或跑测试套件。在 Claude Code 上，除非 `worktree.baseRef` 设置为 `"head"`，`isolation: "worktree"` 默认从远端默认分支切出。当委托要基于默认分支还没有的提交时，先提交它们，用 `git worktree add <path> -b <delegate-branch> HEAD` 建工作树，并在简报里写明那个基线提交。在简报散文里圈住一个文件不等于上锁（**principle-separate-before-serializing-shared-state**）。外科手术式的编辑；上游衍生文件要对照源重新校准。共享原语的改进要移植到所有消费方并逐一验证。放开手提交。
5. 在匹配的界面上验证。「不确定」或用错界面都不算通过，要标出来。
6. rebase 成少量有序提交。后续工作 stack 起来。
   用 **sequence-verifiable-units** 原则技能：每个小单元先构建、验证、提交，再进下一个。
7. 设计有争议时，上线前先 `interrogate`。
8. 走 **Opening a PR** 流程。

代码耦合的工作（一个功能、一次迁移）交给单一 owner，检查点内联。该 owner 在阻塞阶段结束后内部扇出。父层扇出只用于产出独立成物的切片（多项审计、跨子系统调查、竞争性实验）。阶段边界处重写检查点。起一个新 owner，而不是链式打断续传。

**汇报：** 建了什么、选了什么为什么、吞吐检查点、悬而未决的决策。设计备选方案用表格。
