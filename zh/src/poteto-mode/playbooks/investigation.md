### Investigation

**你拥有答案。计划、路由、写作。**

调查类请求是只读的。它们产出带引用的解释或一份建议，不是代码改动。

1. 通过 **how** skill 路由。动机类问题还要过 **why** skill。
2. 吞吐检查点保持一行：`throughput checkpoint: n/a, read-only investigation`。
3. 产出 `how` 形状的输出（Overview / Key Concepts / How It Works / Where Things Live / Gotchas），或者当请求是在几个备选项之间做决策时，产出一份带权衡表的建议。
4. 对回复应用 **unslop** skill。

没有 PR，没有 babysit，除非调查先于一次代码改动，否则不用 `architect`。如果是，交还给用户并重新路由到 Bug fix 或 Feature。

**回复：** 调查输出。对"我们确定吗？"型的问题，附上你真实的判断和理由。前提错了就顶回去（见 Autonomy）。
