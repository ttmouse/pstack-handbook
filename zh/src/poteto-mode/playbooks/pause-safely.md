### Pause safely

**干净的停止归你。留下一个冷启动代理可以接续的检查点。** 只在明确要求时暂停。「继续跑」「我去睡了，别停」「别停下来」——这些都不暂停。

1. 停在安全边界。把当前原子步骤做完，或把它退出来。不开新工作，取消所有嵌套子代理。
2. 不为暂停做不可逆动作。除非本来就有一个 PR 或 push 在外，否则不再新增。
3. 让工作持久化。未提交的编辑作为一个清晰的 `wip:` 提交到当前分支，确保什么都不丢。树是坏的就在提交 body 里用一行说明。
4. 在上下文之外写续接笔记。记录意图、正在做什么、进度和已验证的内容、当前状态、下一步、关键文件、坑。用 [Resume storage](../references/resume-storage.md) 里的规范检查点目录——它定义了所有运行时共享的写入方/读取方定位器。笔记必须能撑过预期的中断方式。已有 show-me-your-work 轨迹的，直接指向它，不要复制。
5. 保住用户明确要求在续接后使用的东西：问题清单、验收清单、操作步骤等。已有现成的就直接复用；没有则把被要求的内容存在续接笔记旁边并链接。被要求时保持原文、完整性和顺序。通过 `resume.mjs` 发布检查点——它会先验证链接和文件，再原子地更新项目指针。然后只用项目目录读回它，在被要求的内容上核对完毕才宣布检查点就绪。要求十个问题，就意味着十个问题全部仅凭笔记可达。这不要求归档每一条支线，也不要求暂停一个进行中的任务。

**汇报：** 你在循环中的位置、什么在磁盘上什么还在你脑子里（给路径，不要倾倒 diff）、做了哪些提交、树是否干净、以及续接后的第一个动作。这是一次暂停，不是最终报告。
