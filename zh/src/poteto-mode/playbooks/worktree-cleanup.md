### Worktree and simulator cleanup

1. 快照并审计。记录 `df -h /`，然后跑已安装插件下的 `skills/poteto-mode/scripts/worktree-audit.mjs`（principle-build-the-lever）。它从 `git worktree list` 读路径，绝不手打——手打的 `myrepo-worktrees/x` 会漏掉一个住在 `.worktrees/myrepo/x` 的（principle-encode-lessons-in-structure）。它按大小、年龄、合并状态、未提交工作、PR 状态、以及最近一次触碰它的聊天来分类每个工作树，然后建议一个桶。transcript 扫描很慢，放后台跑。
2. 桶是建议，不是许可。被钉住和活跃的聊天才是真实产物（principle-prove-it-works）。从用户或你自己的会话列表拿到那个集合，逐一交叉核对每个候选。这个工具曾把用户钉住的一个工作树标成 `safe`，所以钉住的集合说了算。
3. 删除之前先核实用途。对每一条 `verify-recent-chat` 行、或任何你拿不准的东西，扇出子代理去读 transcript，报告该聊天是否被钉住或仍在进行、以及它触碰哪些工作树（principle-guard-the-context-window，transcript 是大宗数据）。一个被钉住的聊天会通过后台子代理往兄弟工作树里 spawn arena 和 repro 目录，即使它们的名字从不出现在会话列表里，也在使用中。按 poteto-mode 的 Subagents 一节为每个子代理选合适的推理档位。
4. 在不可逆损失前暂停。`wip:N` 是 N 个有未提交改动的已跟踪路径，`untracked:N` 是 N 个 git 从未见过的文件。两者都有时两个都打印，比如 `wip:1,untracked:5`。`ignored:N` 是 N 个在审计 `DISPOSABLE` 清单所列构建与缓存目录之外的、被 git 忽略的路径，比如 `.env` 或 `.claude/settings.local.json`，可能别处没有副本。用 `git -C <path> status --porcelain --ignored=matching` 列出它们。再跑 `git -C <path> submodule foreach --recursive 'git ls-files --others --ignored --exclude-standard --directory --no-empty-directory'`，列出已初始化子模块里被忽略的路径。`reflog:N` 是 N 个任何分支、tag、远端都够不到、仅由该工作树的 HEAD 及其 reflog 保住的提交，比如在 detached HEAD 上做的提交。它们就在 `git -C <path> reflog` 打印的条目里。用 `git branch <name> <sha>` 保住需要留的。干净的工作树可以从它的分支恢复。但任何一种未提交工作，目录一删就没了——所以用审计计数所用的同一条调用列出它：`git -C <path> status --porcelain --untracked-files=all --ignore-submodules=none`，用 `git -C <path> diff HEAD --ignore-submodules=none --submodule=log` 展示 diff，然后先拿一个决策。状态里的每一行都是命悬一线的工作，diff 为空绝不等于没有工作。diff 会漏掉所有 untracked 文件，普通的 `git diff` 还可能漏掉子模块。一行 `wip` 点名了某个子模块，代表它里面改动或新增的文件，或在那里做的提交。在子模块里跑同一条 status 调用列出那些文件。`hold-locked` 表示另一个工具或代理锁住了这棵树，原因在 LOCKED 列。`git worktree remove` 会拒绝锁定的树，所以不要绕过它去 `rm -rf`。按 Autonomy：干净、已合并、不在使用中 → 直接清。`wip`、`untracked`、`ignored`、`reflog`、锁定、使用中 → 暂停。
5. 清掉已确认的集合。每个路径跑 `git worktree remove --force <path>`。目录因被忽略的构建产物而残留时，`rm -rf` 掉它，然后 `git worktree prune`。分支引用会存活，工作树分支上的提交保得住。工作树的 HEAD reflog 会随之消失，只有 reflog 够得到的提交就丢了。在子模块里做的提交和该工作树存在一起，也随之消失。用 `df -h /` 确认并重新列表。
6. 模拟器和其他占地方的东西。模拟器通常是下一个大头。`xcrun simctl --set testing delete all`（XCTestDevices 克隆）、`xcrun simctl delete unavailable`、以及 `xcrun simctl runtime list` 后对旧 runtime `runtime delete <id>`。需要更多再清：Xcode 的 `DerivedData` 和 `iOS DeviceSupport`、编辑器的 application-support 缓存、`${CLAUDE_CONFIG_DIR:-$HOME/.claude}/shell-snapshots/` 和旧的 `${CLAUDE_CONFIG_DIR:-$HOME/.claude}/projects/` transcript（**recall** 技能和 Session pickup 要读的近期 transcript 留着）、包缓存（pnpm、uv、brew、yarn）。用户说过要保留的缓存一律不动。

这是唯一一本在没有任何代码评审兜底的情况下删除用户状态的 playbook，所以上面这些闸门就是评审本身。
