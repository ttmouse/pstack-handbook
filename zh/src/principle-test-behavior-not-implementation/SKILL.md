# Test Behavior, Not Implementation

一个测试是对「代码为它的用户做什么」的断言：调用方、终端用户，或另一个服务。行为是这些用户能通过他们使用的接口观察到的东西。包括返回值、错误、他们能读回的状态，以及对代码之外系统的影响，比如发出一个请求、写入一行、发送一条消息。实现是他们观察不到的东西：私有辅助函数、内部调用顺序、中间数据，以及哪个内部协作者干了这件事。

用两个假想的改动来审判每个测试：

- **破坏行为。** 让代码返回错误的值、跳过一个副作用、或把副作用做两遍。如果测试仍然通过，它什么都没证明。常见原因是：断言比契约更松、期望值由被测代码算出、复述一个常量或 prompt 字符串而从未运行读取它的代码、以及对自己构造的数据做断言。
- **改内部实现。** 保持所有可观察结果不变，重构底下的代码。如果测试现在失败了，它钉死在实现上。它会在每次重构时都需要重写，而且照样抓不到 bug。

保留能抓住第一个改动、又能挺过第二个改动的测试。重写或删除其余的。要写出两者兼备的测试，就通过用户的接口用一个具体输入驱动代码。期望值从需求推导，而不是从运行代码推导。断言契约承诺的东西，不少也不多。

决定一切的是契约，不是断言的形状。当「空购物车绝不扣款」是承诺时，断言支付客户端没被调用就是行为。配上一个确实扣款的用例，让测试证明它看得见调用。被 mock 的外部服务收到的载荷是行为，因为那个服务观察得到它。对内部辅助函数的调用是实现，因为没有用户看得见它。当没有记录匹配时，空列表就是精确答案；当测试只需要随便一个结果时，它就是空洞的检查。精确的错误消息钉死了没有调用方会读的措辞。调用方据以分支的错误类型才是契约。

一个测试可以钉住一个不变量而不是一次调用，比如一个必须同时存在于两张表里的键，或一个编译期类型检查。不变量就是行为。常量钉住当值是对用户的承诺时也算行为，比如一个文档化的默认值——那就把这个承诺说出来。
