# Test Behavior, Not Implementation

测试是对「代码使用者能通过接口观察到什么」的主张：返回值、错误、可读回的状态，以及对外部系统的影响。私有辅助函数、内部调用顺序、中间数据，都是实现细节。

用两个假想的编辑来评判每条测试：

- **破坏行为**（一个错误的值、一次被跳过或重复的副作用）。如果测试仍然通过，它什么都没证明。常见原因：断言太松、期望值是由被测代码自己算出来的、断言建立在测试自己构造的数据上。
- **改动内部实现**，保持所有可观察结果不变。如果测试失败了，它就钉死在了实现上。

保住能抓住第一种编辑、且扛住第二种编辑的测试，其余的重写或删除。通过公共接口用具体输入驱动代码，期望值从需求推导。外部服务收到了什么，是行为；对内部辅助函数的调用，不是。「这永远不会发生」的断言，要配一个它确实发生的用例。断言调用方据以分支的错误类型，而不是错误消息。常量钉值在值是对用户的承诺时算行为（比如文档写明的默认值），那就把这个承诺写出来。
