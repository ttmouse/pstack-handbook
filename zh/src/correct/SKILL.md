# Correct

操作者在这个仓库里一直在为同样的错误纠正代理。改造仓库，让下一个代理犯不了这些错。

假设每个贡献者都是一个只看得见自己打开过的文件、照抄最近的示例、走能编译过的最短路径的代理。把仓库设计成：从单个文件看是对的改动，对整个仓库也是对的。

## Find the mistake classes

先读最近的 commit、revert、评审意见、代理指令文件，以及解释变通手段的注释。把错误归成类。同类错误发生两次即算成立。

## Fix each class at the highest level that works

1. **用架构消灭它。** 每份状态一个所有者，每件事一条受支持的做法。隐藏内部实现，让错误的 import 直接失败。用手工同步的列表换成单一事实来源。删掉代理会照抄的旧做法和死代码。
2. **用类型强制，让坏状态写不出来。** 如果坏代码还能编译通过，就加一条 lint 或 CI 检查，让报错信息直接指出该改用哪个文件、类型或函数。如果该模式已经很普遍，只在新增时才失败。
3. **测行为。** 修好或删掉任何一种测试：它检查的行为坏掉了它还能过，或只有内部实现变了它就挂。
4. **文档和代理规则放最后，只写判断题。** 代理跳过它们时什么都不会失败。

## Fix and prove

然后把最高频的类现在就修掉，每类一个 commit。每条新检查都要在真实的历史错误上证明它确实会失败。同一条命令本地和 CI 都要跑。例外写在违规的那一行上，带理由、过期日期和人类的批准。

## Keep the rule table

最后，在代理指令文件里维护一张表，每条规则配对它的强制手段。操作者纠正你时，修掉错误并补上规则。如果规则早已存在却没有任何东西强制它，这就是重复犯错，在同一个改动里按最高层级再修一遍。错误再也无法发生时，删掉规则。

**Reply:** 每个错误类附证据、你选的层级，以及为什么更高的层级行不通。
