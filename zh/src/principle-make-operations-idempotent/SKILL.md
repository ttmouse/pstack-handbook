# Make Operations Idempotent

把操作设计成无论运行多少次、上一次运行停在哪里，都收敛到正确的状态。每个修改状态的操作都应能回答：「如果这个跑两次会怎样？如果上一次运行中途崩溃了会怎样？」

**为什么：** 命令、生命周期操作和处理循环运行在崩溃、重启和重试是常态的地方。如果残留的部分状态会改变下一次运行的结果，那每一次重启都变成一次调试。

**核心思想：** 每一步都从存在的状态推导，而不是从上一次运行想做的事推导。读当前状态，与目标比较，只应用差异。这样写的步骤可以安全重复，因为重复一次会发现无事可做。

一次运行留下的任何东西——锁、临时文件、写了一半的记录、被认领的任务——都必须能被下一次运行识别为过期。判断过期与否要看证据在「上一次运行可能停在任何位置」时仍然成立，而不只在常见情况下成立。一个下一次运行无法判断的标记，会把每次崩溃都变成手工清理。例如，先写到临时路径再 rename 到位，或者按内容而不是按创建顺序比较产物。

**检验标准：**
1. 连续跑两次会发生什么？
2. 如果上一次运行在每一个可能的点都崩溃过，会发生什么？
3. 重新执行会收敛到同一个终态吗？

只要有一个答案是「取决于留下了什么状态」，这个操作就需要一个对账（reconciliation）步骤。
