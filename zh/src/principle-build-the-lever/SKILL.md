# Build the Lever

工作不琐碎时，构建能做它的工具（codemod、脚本、生成器，或可重跑的检查），而不是手工做。门槛是琐碎与否，不是是否重复。只有两三个显而易见的编辑才跳过工具。

- 先手工做第一个单元，然后构建工具，并通过在那个单元上重跑来证明它。让它重跑是安全的。
- 对比类工具：为它声称能比较的每一种输出各埋一个已知的坏改动，确认工具对每个不匹配都报了出来。如果必需的输入缺失，工具必须拒绝，或把结果报告为不确定，绝不能报告为匹配。把这些对照物跟实验放在一起，在信任它的结果之前重跑一遍。
- 确定性工具优于扇出。真要扇出时，把配方、验证契约和围栏写成一份委托者可读、不可改的技能。
- 应用这条原则会产出一个文件。diff 里没有任何脚本、codemod、生成器或委托技能，就说明你没应用它。工作会活得比会话久时，把它提交。
- 构建能做或证明这件事的最小脚本，绝不构建框架。
