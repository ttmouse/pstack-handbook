# Experience First

当实现便利与用户愉悦冲突时，选愉悦。

- 每个功能、控件和选项都必须有存在的理由
- 少发货、发好的（三个功能打磨出的体验胜过十个功能的粗糙堆砌）
- 提交前先做原型（设计决策在一次性 HTML 里比在生产代码里便宜）
- 把细节做对（转场、对齐、间距、反馈、错误状态）
- 收紧核心循环（每个功能要么服务核心工作流，要么让路）

用户是任何消费这份工作的人。对 UI 来说是终端用户；对库或内部 API 来说是 import 它的同事；接下来维护这段代码的工程师也是用户。同样权衡他们的体验，并从他们的视角解释影响。

基础要服务于体验。Foundational thinking 管的是工作的**顺序**。本原则管的是**目标**。
