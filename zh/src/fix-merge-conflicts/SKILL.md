# Fix merge conflicts

## Trigger

分支有未解决的合并冲突，需要一条可靠路径回到可构建状态。

## Workflow

1. 从 git status 和冲突标记找出所有冲突文件。
2. 以最小、正确性优先的编辑逐个解决冲突。
3. 安全时优先保留两侧。否则选能编译、公共行为保持稳定的那一个变体。
4. 用包管理器工具重新生成 lockfile，不手工编辑。
5. 跑编译、lint 和相关测试。
6. 暂存已解决的文件，总结关键决策。

## Guardrails

- 改动保持最小、可读。
- 任何文件里都不得残留冲突标记。
- 解决冲突期间不做大范围重构。
- 解决过程中不 push、不打 tag。

## Output

- 已解决的文件
- 值得注意的解决取舍
- 构建/测试结果
