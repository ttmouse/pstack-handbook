# Fix merge conflicts

## 触发

分支有未解决的合并冲突，需要一条可靠的路径达到可构建状态。

## 工作流

1. 从 git status 和冲突标记检测所有冲突文件。
2. 用最小、正确性优先的编辑解决每个冲突。
3. 安全时优先保留两侧。否则选择能编译且保持公开行为稳定的变体。
4. 用包管理器工具重新生成 lockfile，而不是手改。
5. 运行编译、lint 和相关测试。
6. 暂存已解决的文件，总结关键决策。

## 护栏

- 保持改动最小且可读。
- 任何文件里都不留冲突标记。
- 解决冲突期间避免大范围重构。
- 冲突解决期间不推送、不打 tag。

## 输出

- 已解决的文件
- 值得注意的解决决策
- 构建/测试结果
