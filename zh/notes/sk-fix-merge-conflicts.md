这本是「分支撞了、解完冲突要能编译」的可靠路径。流程是：从 git status 和冲突标记找出所有冲突文件，逐个做最小、正确性优先的解决；能安全保留两侧就保留，不行就选能编译且公开行为不变的变体；lockfile 交给包管理器重新生成而不是手改；最后跑编译、lint、测试确认，再暂存并汇报关键决策。

护栏里有几条值得记住的「不做什么」：不留任何冲突标记、解冲突期间不顺手重构、不推送不打 tag（先在本地确认干净，发布是下一步的事）。

什么时候用它：rebase 或 merge 之后满屏冲突标记，想要一条到可构建状态的路径。什么时候别用：冲突是 CI 失败（归 fix-ci），或者两个分支语义冲突大到需要人来拍板设计取向——这本只保证「能编译、行为不变」，不替你做产品决策。
