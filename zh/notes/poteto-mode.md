这份文件是整套体系的**总管本体**：你敲 `/pstack:poteto-mode` 或宿主自动路由时，AI 完整读的就是它。所有行为——挑哪本清单、什么时候停、怎么派活、怎么汇报——都由它规定。读懂它，等于读懂整套体系怎么运转。

**按块读，不用从头顺到尾：**

- **平台适配（Platform Adaptation）**：开头一大段讲各运行时（Codex、Pi、Copilot 等）怎么把 Claude 的工具名换成自家对应物，外加待办清单工具的兜底方案。不换平台可以跳过，只用知道「todo 没工具时退化为不提交的 todo.md」。
- **不可妥协项（Non-negotiables）**：硬规矩。第一条是「复述目标 + 最小改动再动手」；还有启动任何 agent 第一行必须让它读 worker.md；有分歧跑原型而不是问人；写代码先说数据形状；提交前 `/deslop`、评审前 no-comments；测出的数字走 benchmark-checklist。这些是任何清单都绕不开的底线。
- **Principles（原则）**：原则索引，按 Core / Architecture / Verification / Delegation / Meta 五组排。AI 拿当前步骤撞每条的适用条件，撞中才读全文——所以你看不到全文，只看到「何时适用」。（新版不再有 Comments 一节，触发清单也缩到 13 行，不再路由到 how。）
- **Autonomy（自主性）**：什么时候直接做（可逆工作、外部动作照做不问）、什么时候必须停下来（强推共享分支、部署、删数据、给客户发消息），以及「别停 / 跑完为止」这类会话级覆盖。还有一条容易被忽略：**「不」是可以接受的答案**——被问、被加范围、被展示方案时，要给真判断，不谄媚。
- **Subagents（子代理）**：派活的规矩——默认用 `pstack:poteto-agent`、后台运行、给文件指针不给内联上下文、按角色配模型；默认开全新子代理而非续用；没有独立评审者时评审闸门保持关闭，绝不拿自己的评审当独立裁决。花钱最多的部分就在这节。
- **写回复**：短陈述句、先说用户这边变了什么、每个论断带证据或标签、绝不把你能跑的检查交给人。这是你验收它工作的模板。
- **Playbooks（流程清单）**：22 本内置清单的名字列表，外加项目自定义 playbook 机制（`.agents/playbooks/`，用 extends 挂到内置清单上，配套 check-playbooks.mjs 校验脚本）。路由的依据就在这节——你说的话和哪条对上，就走哪本。
- **Models / Reasoning effort**：哪个角色用哪个模型、用什么推理强度，以及 `pstack-models.md` 覆盖表怎么逐行生效。改成本就改这里（配合 setup-pstack）。

**读法建议**：先读「不可妥协项」和「写回复」（这两块决定你怎么用它、怎么验它），再读「Playbooks」理解路由，最后按需查 Subagents 和 Models。它比任何一本清单都长，因为它是唯一一份每次任务都要全文读的文件——固定开销就在这。
